# 📰 news-pipeline

news-pipeline - ETL-пайплайн на Python, который каждый час собирает новости с новостных сайтов (Лента.ру, ТАСС, Интерфакс). Новости очищаются и сохраняются в PostgreSQL, где их можно анализировать с помощью SQL-запросов.

![Схема пайплайна](C:\projects\news-pipeline\docs)

## Стек
- Python: requests, feedparser, pandas, psycopg2, python-dotenv
- PostgreSQL
- Git, Планировщик Windows

## Как устроен пайплайн

**Extract** (`extract.py`)
- забирает RSS-ленты через requests с таймаутом 10 секунд
- при ошибке сети делает до 3 попыток с паузой 2 секунды
- разбирает xml через `feedparser`
- результат сохраняется в `data/raw_news.csv`
- если все сайты недоступны выводится сообщение, пайплайн останавливается, а прошлый CSV не перезаписывается

**Transform** (`transform.py`)
- читает данные из файла `data/raw_news.csv`
- даты приводятся к единому стандарту по UTC
- преобразует название источников в единый стиль
- дубли удаляются с помощью pandas по `url`
- добавляет новую колонку с временем запуска
- сохраняет в data/clean_news.csv

**Load** (`load.py`)
- данные читаются из `data/clean_news.csv`
- подключается к базе `news_db` с помощью библиотеки `psycopg2`
- настройки подключения и пароль лежат в файле `.env`, он не попадает на GitHub так как записан в `.gitignore`
- загрузка идемпотентна: на колонке `url` стоит ограничение `UNIQUE`, а вставка идёт через `INSERT ... ON CONFLICT (url) DO NOTHING` - уже существующие новости пропускаются, поэтому повторный запуск не создаёт дублей
- сохранение при помощи команды `conn.commit()`
- в конце выводит, сколько новостей было, стало и добавлено: в базу попадают только новые новости (инкрементальная загрузка)

**Автозапуск**
- `main.py` запускает все три этапа по очереди одной командой
- если Extract не собрал ни одной новости, пайплайн останавливается и не трогает данные из прошлого запуска
- `run_pipeline.bat` переходит в папку проекта, включает виртуальное окружение и запускает `main.py`
- Планировщик Windows запускает батник каждый час
- весь вывод пишется в `data/pipeline.log`

## Особенности
- таймауты и повторные попытки при загрузке: нестабильный источник не вешает и не роняет пайплайн
- если один источник недоступен, остальные всё равно загружаются
- идемпотентная загрузка в PostgreSQL через `UNIQUE` и `ON CONFLICT`
- инкрементальная загрузка: в базу попадают только новые новости
- защита от пустых данных
- пароль и настройки подключения хранятся в `.env`, а не в коде
- структура таблицы описана в `schema.sql`

## Как запустить
1. `git clone https://github.com/poliuyy/news-pipeline.git`
2. `python -m venv venv` и `venv\Scripts\activate`
3. `pip install -r requirements.txt`
4. Создать в PostgreSQL базу `news_db` и выполнить `schema.sql`
5. Создать в корне файл `.env`:
 ```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=news_db
DB_USER=postgres
DB_PASSWORD=
 ```
6. Запустить:`python main.py`
